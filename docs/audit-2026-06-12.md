## Critical

### [Accessibility] Sudoku board cells are non-focusable divs
- **Location:** `resources/views/sudoku/show.blade.php` lines 117–143
- **Issue:** Every cell is a `<div>` with `@click`. No tab stop, no initial focus — keyboard-only users cannot enter the board without a prior mouse click. Arrow-key navigation requires `selected !== null`, which is never true on load.
- **Fix:** Add `tabindex="0"` and `role="gridcell"` to each cell, `role="grid"` on the board, `role="row"` wrappers. Set `this.selected = 0` in `init()`. Add per-cell `:aria-label` with row/column/value.

### [Accessibility] Cryptogram cipher spans and alphabet tiles are non-focusable
- **Location:** `resources/views/cryptogram/show.blade.php` lines 83–98, 113–133; `resources/js/cryptogram.js` lines 183–187
- **Issue:** Cipher letter positions and alphabet tiles are plain `<span>`/`<div>` with `@click`. `handleKey` only fires when `this.selected !== null`, which requires a mouse click to establish — keyboard users are locked out entirely.
- **Fix:** Convert alphabet tiles to `<button>` elements (or add `tabindex="0" role="button"`). Auto-select the first unlocked cipher letter in `init()`.

### [Accessibility] Completion modal has no focus management and is not a dialog
- **Location:** `resources/views/sudoku/show.blade.php` lines 248–299; `resources/views/cryptogram/show.blade.php` lines 154–201
- **Issue:** On puzzle completion, the overlay appears but focus stays on the page. No `role="dialog"`, no `aria-modal`, no `aria-labelledby`, no Escape handler. Screen readers receive no announcement. Keyboard users must tab blindly through the whole page to reach "Play another".
- **Fix:** Add `role="dialog" aria-modal="true" aria-labelledby="completion-title"` to the inner panel. In the `submitSolution()` callback, use `$nextTick` to move focus into the modal. Add Escape-to-dismiss and a tab-cycle focus trap.

## High

### [Security] Client-controlled `elapsed_seconds` and `mistakes` overwrite server state
- **Location:** `SudokuController.php:106–110, 143–147`; `CryptogramController.php:99–104, 143–146`
- **Issue:** Both `saveSession` and `completeSession` accept these fields from the client and persist them directly with only `integer|min:0` validation. A player can submit `elapsed_seconds=0, mistakes=0` at completion to fabricate a perfect score.
- **Fix:** Compute `elapsed_seconds` server-side from timestamps. At minimum, reject submissions where either value is less than what is already stored: `abort_if($data['elapsed_seconds'] < $session->elapsed_seconds, 422)`.

### [Security] Single shared browser token authorizes all sessions
- **Location:** `resources/js/sudoku.js:67–72`; `resources/js/cryptogram.js:52–57`
- **Issue:** `getOrCreateToken()` reads/writes a single `puzzlebox_token` localStorage key shared across every puzzle type. Leaking this UUID (XSS, shared device, network trace) grants access to every session for that browser. The token never rotates.
- **Fix:** Generate a distinct session token per puzzle session server-side, store it in the session record, and return it to the client on `startSession`. Scope each token to exactly one game session.

### [Security] Sudoku `board_state` cells and notes have no per-element validation
- **Location:** `SudokuController.php:94–101, 121–128`
- **Issue:** `board_state.cells` is validated as an array of 81 items but individual elements are unconstrained — any type, any value. Arbitrary data is persisted to the JSON column and iterated in `completeSession`.
- **Fix:** Add `'board_state.cells.*' => 'nullable|integer|min:1|max:9'` and `'board_state.notes.*' => 'array'` with `'board_state.notes.*.*' => 'integer|min:1|max:9'`.

### [Security] Cryptogram `guesses` map is unbounded
- **Location:** `CryptogramController.php:88–104, 110–167, 176–178`
- **Issue:** `guesses` is validated only as `required|array` — no key count limit, no format enforcement on keys or values. A client can send thousands of arbitrary key-value pairs persisted verbatim to `board_state`.
- **Fix:** Add `'board_state.guesses' => 'required|array|max:26'`, `'board_state.guesses.*' => 'nullable|string|size:1|regex:/^[A-Z]$/'`. Apply the same to `hintSession`.

### [Code Quality] Timer `setInterval` is never cleared on unload
- **Location:** `resources/js/sudoku.js:412–415`; `resources/js/cryptogram.js:291–294`
- **Issue:** `startTimer()` sets `this.timerInterval` but it is only cleared on successful completion. Navigation away or reload leaves the interval running, holding a closure reference and preventing GC.
- **Fix:** Add an Alpine `destroy()` lifecycle hook that calls `clearInterval(this.timerInterval)` and `clearTimeout(this.saveTimer)`.

### [Code Quality] `keydown` listener is never removed — leak and duplicate handler risk
- **Location:** `resources/js/sudoku.js:61`; `resources/js/cryptogram.js:46`
- **Issue:** `init()` calls `document.addEventListener('keydown', e => this.handleKey(e))` with an inline arrow function that cannot be removed. Re-mounting the component stacks duplicate handlers.
- **Fix:** Store the bound handler as `this._keyHandler = e => this.handleKey(e)` and call `document.removeEventListener('keydown', this._keyHandler)` in `destroy()`.

### [Code Quality] N+1 query: `$session->puzzle` loaded lazily in every action
- **Location:** `SudokuController.php:134, 191, 237`; `CryptogramController.php:123, 187`
- **Issue:** Every action that reads `$session->puzzle` triggers a separate SELECT. `$session->puzzle->solution_data` throws if the puzzle was hard-deleted — there is no null guard.
- **Fix:** Add `$with = ['puzzle']` to `GameSession`, or eager-load via route model binding. Add `abort_unless($session->puzzle, 404)` at the top of each action that accesses it.

### [Accessibility] No live regions — dynamic state changes are never announced
- **Location:** `resources/views/sudoku/show.blade.php` lines 44–97; `resources/views/cryptogram/show.blade.php` lines 36–76
- **Issue:** Session error banners, wrong-answer messages, hint reveals, and the completion event all appear/disappear silently. Screen readers announce none of these.
- **Fix:** Add `aria-live="polite" aria-atomic="true"` to error message divs in both show views. Use a visually-hidden `aria-live="assertive"` status element for hints and completion.

### [Accessibility] Error states communicated by color alone
- **Location:** `resources/js/sudoku.js:389–397`; `resources/js/cryptogram.js:316–334`
- **Issue:** Conflict cells turn red, hints turn amber — no other visual distinction. Red-green color-blind users cannot differentiate conflict, hint, wrong, and correct states.
- **Fix:** Add a non-color indicator: underline or warning icon for Sudoku conflict cells; `<span class="sr-only">(conflict)</span>` / `(hint)` inside affected cells.

### [Accessibility] Number-pad buttons have no accessible label or state
- **Location:** `resources/views/sudoku/show.blade.php` lines 165–175
- **Issue:** Buttons render their digit as visible text only. No `aria-label` with a verb, no `aria-pressed` to reflect the `highlightValue` active state.
- **Fix:** Add `:aria-label="\`Enter ${n}\`"` and `:aria-pressed="highlightValue === n"` to each button.

### [Accessibility] Notes mode toggle has no `aria-pressed`
- **Location:** `resources/views/sudoku/show.blade.php` lines 152–161
- **Issue:** The "Notes On / Notes Off" button changes text label but exposes no pressed state to assistive technology.
- **Fix:** Add `:aria-pressed="notesMode"` to the toggle button.

### [Accessibility] Hamburger button has no accessible label
- **Location:** `resources/views/layouts/navigation.blade.php` line 69
- **Issue:** The mobile hamburger `<button>` contains only an SVG with no `aria-label`, `aria-expanded`, or `title`. Screen readers announce it as an unlabeled button.
- **Fix:** Add `aria-label="Open navigation menu"` and `:aria-expanded="open"`. Add `aria-hidden="true"` to the SVG.

## Medium

### [Accessibility] User-account dropdown button missing `aria-haspopup` and SVG not hidden
- **Location:** `resources/views/layouts/navigation.blade.php` lines 35–39
- **Fix:** Add `aria-hidden="true"` to the chevron SVG; add `aria-haspopup="menu"` and `:aria-expanded` to the trigger button.

### [Accessibility] Pencil notes have no screen-reader equivalent
- **Location:** `resources/views/sudoku/show.blade.php` lines 131–142
- **Fix:** Bind `:aria-label="\`Row ${r}, Column ${c}, notes: ${noteList}\`"` on cells with notes. Add `aria-hidden="true"` to note digit spans.

### [Accessibility] Cryptogram quote tokens have no accessible structure
- **Location:** `resources/views/cryptogram/show.blade.php` lines 81–105
- **Fix:** Wrap the quote in `role="group" aria-label="Encoded quote"`. Add per-character `:aria-label="'Cipher: ' + cipher + ', guess: ' + (guess || 'unsolved')"`. Add a visually-hidden reactive `<p>` with the current decoded state.

### [Accessibility] Back link arrow character read aloud by screen readers
- **Location:** `resources/views/sudoku/show.blade.php` lines 5–8; `resources/views/cryptogram/show.blade.php` lines 5–8
- **Fix:** Wrap the arrow in `<span aria-hidden="true">←</span>`.

### [Accessibility] Arrow-key navigation requires prior mouse click to initialize
- **Location:** `resources/js/sudoku.js` lines 339–368
- **Fix:** Set `this.selected = 0` in `init()`. Add a `focus-visible` ring style to the selected cell.

### [Accessibility] Cryptogram Tab key unconditionally calls `preventDefault`
- **Location:** `resources/js/cryptogram.js` lines 243–245
- **Issue:** Tab is swallowed whenever a letter is selected, preventing navigation to page controls or the nav bar — an unintended partial focus trap.
- **Fix:** Only intercept Tab for in-game cipher letter cycling. Do not call `preventDefault()` when the intent is to leave the puzzle area.

### [Security] Sequential integer session IDs enable enumeration
- **Location:** `routes/web.php:32–52, 62–72`
- **Issue:** Routes bind `GameSession` by auto-increment PK. A 403 confirms a session exists; 404 means it does not. Leaks total session count.
- **Fix:** Add a `uuid` column to `game_sessions`, override `getRouteKeyName()` to `'uuid'`, and update routes to resolve by UUID.

### [Security] `hints_used` in `$fillable` enables mass-assignment reset
- **Location:** `app/Models/GameSession.php`
- **Fix:** Remove `hints_used` from `$fillable`. Increment only via `$session->increment('hints_used')`.

### [Security] Anonymous session takeover by authenticated user
- **Location:** `SudokuController.php:75–77, 268–276`; `CryptogramController.php:72–74, 213–221`
- **Issue:** `startSession` links any `user_id = null` session matching the supplied token to the authenticated user. Combined with the shared token issue, a token leak grants permanent claim over all anonymous sessions.
- **Fix:** Scope the linking path — only link if the session was created within the current auth session's lifetime.

### [Security] Per-IP rate limits only; no per-session throttle on check endpoint
- **Location:** `routes/web.php:27–72`
- **Fix:** Add a per-session rate limit using `RateLimiter::for` keyed on session ID.

### [Security] `SUDOKU_MAX_HINTS` config name misleading; zero-value behavior is inverted
- **Location:** `config/puzzlebox.php:15`; `.env.example`
- **Issue:** Used by both game types. Comment says `0 = unlimited` but `>= $maxHints` fires immediately when `$maxHints === 0`, blocking all hints.
- **Fix:** Rename to `PUZZLEBOX_MAX_HINTS`. Fix the comment: `0 = no hints`; use `null`/unset for unlimited.

### [Code Quality] `missing_letters` returned by controller but never read by JS
- **Location:** `CryptogramController.php:126–141`; `resources/js/cryptogram.js` (`submitSolution`)
- **Issue:** Players who leave letters blank get no feedback distinguishing "wrong" from "missing".
- **Fix:** Handle `data.missing_letters` in `submitSolution()` and surface it in the UI.

### [Code Quality] `authorizeSession` duplicated verbatim in both controllers
- **Location:** `SudokuController.php:268–276`; `CryptogramController.php:213–221`
- **Fix:** Extract to a trait (`App\Http\Concerns\AuthorizesGameSession`) or shared `GameController` base class.

### [Code Quality] `getOrCreateToken()`, `post()`, `patch()` duplicated in both JS files
- **Location:** `resources/js/sudoku.js:66–73, 511–525`; `resources/js/cryptogram.js:51–58, 339–353`
- **Fix:** Extract to `resources/js/utils.js` and import in both game files.

### [Code Quality] `startTimer()` and `formatTime()` duplicated in both JS files
- **Location:** `resources/js/sudoku.js:411–421`; `resources/js/cryptogram.js:291–300`
- **Fix:** Extract timer logic into a shared mixin object spread into each game's component definition.

### [Code Quality] Hint endpoint uses client-supplied guesses instead of server-authoritative state
- **Location:** `CryptogramController.php:177`
- **Issue:** A malicious client can send an empty `guesses` object to hint already-guessed letters, inflating `hints_used`.
- **Fix:** Use `$session->board_state['guesses']` instead of client-supplied data.

### [Code Quality] Only 12 hardcoded quotes; duplicates guaranteed above count 12
- **Location:** `app/Services/Cryptogram/Generator.php:7–56`
- **Fix:** Expand the quote pool; add a pre-insert uniqueness check; or move quotes to a seeded DB table.

### [Code Quality] Sudoku index issues up to 10 queries per page load
- **Location:** `SudokuController.php:21–35`
- **Fix:** Batch with a single `whereIn('difficulty', $difficulties)` query for today's scheduled puzzles, then one fallback query for gaps. Maximum 2 queries total.
